# 测试与质量保证指南

Knotra 测试的重点不仅在于验证单个方法的功能正确性，更在于验证**代际演进、依赖传播、在途排空、生命周期清理以及 ClassLoader 隔离与回收**。

---

## 六大核心测试原则

1. **职责分离**：纯业务逻辑使用常规 JUnit 单元测试；只有涉及动态装配、热替换与传播行为时才启动 `KnotraRuntime`。
2. **测试隔离**：每个测试用例创建独立的 Runtime 实例，在 `try-with-resources` 或 `@AfterEach` 中完成关闭。
3. **严格设置超时预算**：所有同步等待统一使用带超时的 `awaitSettled(Duration)` 或 `requireActive(Duration)`，严禁无界等待。
4. **精确断言目标状态**：操作级收敛（Settlement）完成不代表所有节点都处于 ACTIVE，需显式断言目标挂载点的实际状态。
5. **异常与重试可观测**：测试资源销毁失败时允许进入 FAILED，显式发起 retry 后再断言 DISPOSED。
6. **类加载器垃圾回收断言**：插件卸载测试必须验证弱引用（`WeakReference`）能够被 JVM GC 彻底回收。

## 基础测试骨架

以下为编写动态热替换测试的标准测试骨架（参考 [QuickStartExampleTest](../../knotra-docs-examples/src/test/java/io/knotra/docs/QuickStartExampleTest.java)）：

```java
final class ServiceReplacementTest {

    @Test
    void dynamicProxyFollowsProviderReplacement() throws Exception {
        Duration timeout = Duration.ofSeconds(5);

        try (KnotraRuntime runtime = KnotraRuntime.create()) {
            // 1. 发布 v1 实现
            PublicationChange<Greeting> firstChange =
                    runtime.publish(Greeting.class, new ConstantGreeting("v1"));
            Publication<Greeting> greeting = firstChange.publication();
            firstChange.awaitSettled(timeout);

            // 2. 挂载动态依赖 Greeting 的消费方
            BeanDefinition<GreetingRenderer> definition = Beans
                    .component("renderer")
                    .with(Beans.dynamic(Greeting.class))
                    .create(GreetingRenderer::new)
                    .provideAs(RenderedGreeting.class)
                    .build();

            MountHandle handle = definition.mount(runtime);
            handle.requireActive(timeout);

            // 3. 验证 v1 输出
            assertEquals("v1: Hello, Knotra", render(runtime));

            // 4. 热替换为 v2 实现
            PublicationChange<Greeting> secondChange =
                    greeting.update(new ConstantGreeting("v2"));
            SettlementReport report = secondChange.awaitSettled(timeout);

            // 5. 验证消费方未失败且自动切换为 v2
            assertFalse(report.hasFailedMounts());
            handle.requireActive(timeout);
            assertEquals("v2: Hello, Knotra", render(runtime));
        }
    }

    private String render(KnotraRuntime runtime) {
        return runtime.require(RenderedGreeting.class).render("Knotra");
    }
}
```

## 状态与断言规范

### 1. 断言挂载点就绪（`requireActive`）
这是最直接、最推荐的就绪断言方式：

```java
// 等待并断言在 5 秒内进入 ACTIVE
handle.requireActive(Duration.ofSeconds(5));
```

若超时或发生异常，会抛出 `MountNotActiveException`，可用于异常测试：

```java
MountNotActiveException error = assertThrows(
        MountNotActiveException.class,
        () -> brokenHandle.requireActive(Duration.ofSeconds(2)));

assertEquals(ComponentState.FAILED, error.state());
```

### 2. 区分等待范围
* **`PublicationChange.awaitSettled(...)`**：操作级收敛，递归等待本次变更触发的子树完成。
* **`MountHandle.whenSettled()`**：仅等待该挂载点自身的状态过渡（返回 `ComponentState`），不覆盖其拥有的子节点。

## 依赖传播与影响集测试

### 1. 验证动态代理消费方零重建
当更新被 `Beans.dynamic` 依赖的能力时，消费方实例无需重建：

```java
PublicationChange<Greeting> change = publication.update(new ConstantGreeting("v2"));
SettlementReport report = change.awaitSettled(Duration.ofSeconds(5));

// 动态代理消费方不受重建影响，因此受影响集为空，且无失败挂载
assertFalse(report.hasAffectedMounts());
assertFalse(report.hasFailedMounts());
```

### 2. 验证固定代际消费方自动重建
当更新被 `Beans.fixed` 依赖的能力时，消费方会自动进入重建链路：

```java
PublicationChange<Greeting> change = publication.update(new BrokenGreeting());
SettlementReport report = change.awaitSettled(Duration.ofSeconds(5));

// 固定依赖消费方受影响，且由于 BrokenGreeting 抛错导致挂载失败
assertTrue(report.hasAffectedMounts());
assertTrue(report.hasFailedMounts());
assertEquals(ComponentState.FAILED, report.failedMounts().getFirst().state());
```

## 结构事务测试

测试多操作原子提交：

```java
TransactionReceipt<StagedRegistration<Message>> receipt =
        runtime.advanced().transact(transaction ->
                transaction.provide(runtime.root(), Message.class, new SimpleMessage("data")));

StagedRegistration<Message> staged = receipt.value();
assertEquals(Message.class, staged.key().type());

SettlementReport report = receipt.awaitSettled(Duration.ofSeconds(5));
assertEquals("data", runtime.require(Message.class).value());

// 撤销该注册
runtime.advanced().transact(tx -> {
    tx.revoke(staged);
    return null;
}).awaitSettled(Duration.ofSeconds(5));

assertTrue(runtime.root().view().find(Message.class).isEmpty());
```

## ClassLoader 回收与 GC 验证测试

在插件工程中，必须编写测试以确保插件卸载后 ClassLoader 能够被彻底回收：

```java
@Test
void pluginClassLoaderIsGarbageCollectedAfterUnload() throws Exception {
    WeakReference<ClassLoader> loaderRef;

    try (KnotraRuntime runtime = KnotraRuntime.create();
         Pf4jArtifactAdapter adapter = Pf4jArtifactAdapter.create(pluginsDir, runtime, Set.of("com.example.contract"))) {

        // 1. 加载插件并记录其 ClassLoader 弱引用
        ArtifactSnapshot artifact = adapter.loadArtifactAsync(pluginJar).toCompletableFuture().get(10, TimeUnit.SECONDS);
        ClassLoader pluginLoader = adapter.classLoaderOf(artifact.id()).orElseThrow();
        loaderRef = new WeakReference<>(pluginLoader);

        // 2. 挂载并使用
        ArtifactFactoryHandle.NoConfig factory = adapter.factories().resolveNoConfig("demo").orElseThrow();
        MountHandle mount = factory.mount(runtime.root(), "demo-mount");
        mount.requireActive(Duration.ofSeconds(5));

        // 3. 释放挂载并卸载插件
        mount.disposeAsync().toCompletableFuture().get(10, TimeUnit.SECONDS);
        adapter.unloadArtifactAsync(artifact.id()).toCompletableFuture().get(10, TimeUnit.SECONDS);
    }

    // 4. 显式触发 GC 并断言弱引用已被回收
    for (int i = 0; i < 10 && loaderRef.get() != null; i++) {
        System.gc();
        Thread.sleep(100);
    }

    assertNull(loaderRef.get(), "插件 ClassLoader 必须在卸载后被 JVM GC 完全回收");
}
```
